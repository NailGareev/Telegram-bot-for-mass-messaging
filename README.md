# Бот для билетов с QR-кодом

Telegram-бот для администраторов мероприятия: выдаёт билеты с уникальным QR-кодом и ФИ гостя,
проверяет их на входе и ведёт список клиентов.

**Всё управление — в приложении Mini App** (кнопка слева от поля ввода сообщения). В чате с ботом
нет ни меню, ни клавиатуры: туда бот присылает только **выданные билеты и информацию о них**.
Бот отвечает **только администраторам** — всем остальным он не пишет вообще ничего.

## Что умеет приложение

- 🎟 **Новый билет** — ФИ (обязательно), группа, университет и телефон (необязательно), количество
  билетов (до 10 на одни данные). После выдачи билеты приходят вам в чат: картинка с QR и ФИ
  и сообщение с данными клиента. Если на этот телефон билет уже выдавался, приложение предупредит.
- 📷 **Сканировать** — камера Telegram, проверка по фото QR или по номеру билета. При повторном
  сканировании приложение показывает, что билет уже использован, и когда был первый проход.
  Сканировать можно подряд, приложение не закрывается.
- 📥 **Массовый залив** — загрузите список клиентов файлом `.txt` или `.docx` (до 5 МБ, до 300 клиентов
  за раз): ИИ (Groq) сам найдёт в нём клиентов в любом оформлении, в том числе в таблице, и учтёт
  количество билетов («2 билета»). Перед выдачей вы увидите распознанное и можете поправить данные
  или убрать лишних; клиенты, которые уже есть в базе, отмечены и по умолчанию выключены. Билеты приходят
  в чат архивами `.zip` и списком `issued.txt`. Без ключа Groq список разбирается по простым правилам:
  одна строка — один клиент в порядке «ФИ, группа, университет, телефон».
- 📋 **Список и поиск** — все купившие, поиск по ФИ, телефону, группе и номеру, карточка билета с
  картинкой, отправка билета в чат, выгрузка списка в TXT (файл приходит в чат), удаление билета.
- 📊 **Статистика** — сколько выдано и прошло, разбивка по админам и университетам.
- 👥 **Админы** — добавление по нику (`@username`) или Telegram ID, разрешения по разделам.
- 🎨 **Дизайн билета** — загружаете картинку (ФИ в ней быть не должно), ИИ находит место под QR
  **и место, где на билете можно печатать ФИ гостя**. Места правятся прямо на картинке: нажатием,
  ползунками размера, выравниванием; переключатель «Печатать ФИ на билете». Подсказка словами
  («ФИ над QR») заставляет ИИ исправить только то, на что вы указали.
- 🗑 **Сброс списка** — полное удаление всех билетов (резервная копия в TXT приходит в чат).
- ⚙️ **Настройки** — ключ Groq. Раздел только у главного администратора.

**Разрешения.** Главному администратору (из `MAIN_ADMIN_IDS`) доступно всё. Остальным разделы
включаются по отдельности; по умолчанию — «Новый билет» и «Сканировать».

- «Список и поиск» открыт всем, но без этого разрешения админ видит только билеты, которые выдал сам.
- Удалить билет может главный администратор или тот админ, который его выдал.
- Админ с разделом «Админы» может выдавать другим только те разрешения, которые есть у него, и не
  может менять свои. «Настройки» выдать нельзя.
- Админ, добавленный по нику, получает доступ, когда первый раз напишет боту `/start`.

**Что приходит в чат:** билеты после выдачи (и по кнопке «Прислать билет в чат»), архивы и список
после массового залива, выгрузка списка в TXT, резервная копия перед сбросом, сообщения об
обновлении проекта. На любое другое сообщение бот отвечает подсказкой, где приложение.

## Установка на сервер (Debian 10 / 11 / 12 / 13)

```bash
git clone https://github.com/NailGareev/Telegram-bot-for-mass-messaging.git
```

```bash
cd Telegram-bot-for-mass-messaging
```

```bash
sudo bash install.sh
```

Скрипт спросит только **токен бота** (от [@BotFather](https://t.me/BotFather)) и **Telegram ID
главного администратора** (его покажет [@userinfobot](https://t.me/userinfobot)), а остальное
сделает сам:

- поставит нужные пакеты и библиотеки (на Debian 10 и 11 системный Python слишком старый,
  поэтому скрипт ставит отдельный Python 3.12 в папку проекта, не трогая системный);
- проверит токен у Telegram;
- зарегистрирует бота как службу `ticket-bot` — он запустится сразу и будет стартовать сам
  после перезагрузки сервера.

Скрипт можно запускать повторно — например, после обновления:

```bash
git pull && sudo bash install.sh
```

Управление: `systemctl status ticket-bot`, `systemctl restart ticket-bot`,
журнал — `journalctl -u ticket-bot -f`.

## Обновление проекта из чата

Главный администратор обновляет бота, не заходя на сервер:

1. На GitHub откройте репозиторий → **Code → Download ZIP**.
2. Пришлите этот zip-файл в чат с ботом.
3. Бот покажет, сколько файлов добавится, изменится и удалится, и спросит подтверждение.
4. Нажмите **«Установить и перезапустить»** — через несколько секунд бот напишет, что обновился.

Что при этом происходит: бот ставит новые зависимости (если они изменились), проверяет пробным
запуском, что новая версия стартует, сохраняет копию текущей версии (`data/backup/`, последние 5)
и заменяет файлы проекта. Файл `.env`, база билетов, загруженный дизайн, ключи и настройки
не затрагиваются. Если новая версия не запустилась три раза подряд, прежняя возвращается сама.

Бот перезапускается сам, если запущен как служба (`install.sh`) или через `python run.py`.
При запуске вручную (`python -m bot`) он после установки остановится — запустите его снова.
Telegram не позволяет боту скачивать файлы больше 20 МБ; архив проекта весит меньше 1 МБ.
Обновление принимает только главный администратор.

## Запуск на своём компьютере

Нужен Python 3.10+.

```bash
python run.py
```

При первом запуске `run.py` создаст файл `.env` и попросит вписать в него `BOT_TOKEN` и
`MAIN_ADMIN_IDS`. После этого запустите `python run.py` ещё раз — он сам создаст виртуальное
окружение `.venv`, установит зависимости и запустит бота. Все следующие запуски — той же командой.

## Как приложение получает адрес

Telegram открывает мини-приложения только по HTTPS, поэтому бот при запуске:

1. поднимает на компьютере или сервере веб-сервер (порт `8080`, меняется через `WEBAPP_PORT`);
2. открывает к нему бесплатный туннель Cloudflare. Для этого нужна программа `cloudflared`:
   бот ищет её в системе и рядом с `run.py`, а если не находит — сам скачивает официальную
   сборку с GitHub в папку `data/` (Windows и Linux; на macOS — `brew install cloudflared`);
3. ставит администраторам кнопку Mini App с полученным адресом.

Адрес туннеля меняется при каждом запуске — бот сам обновляет кнопку. Регистрация в Cloudflare
не нужна. Если у вас есть свой сервер с доменом и HTTPS, укажите его в `WEBAPP_URL` (он должен
вести на порт бота) — тогда туннель не используется.

Модели Groq (для картинок и для текста) бот подбирает сам: если модель по умолчанию снята с
поддержки, он берёт список моделей вашего ключа, пробует подходящие и запоминает рабочую. В
приложении, в «Настройках», можно выбрать модели вручную и нажать **«Проверить ИИ»** — кнопка покажет,
работает ли ключ, текстовая модель и модель для картинок, и какие модели вам доступны. `MINI_APP=off` выключает приложение, `TUNNEL=off` запрещает
автоматический туннель. Если приложение не поднялось, причина — в журнале бота, а в ответ на
`/start` бот предупредит, что приложение недоступно.

Адрес приложения в консоль не выводится — он сам попадает в кнопку Mini App.

## Журнал

По умолчанию бот пишет в консоль только предупреждения и ошибки. Чтобы видеть подробный журнал
(запуск, каждое обработанное сообщение, запросы Mini App), добавьте в `.env` строку
`LOG_LEVEL=INFO` и перезапустите бота.

## ФИ на билете

На каждом билете печатается ФИ гостя. Шрифт — Inter (лицензия OFL, лежит в `assets/fonts/`),
он поддерживает кириллицу. Размер букв подбирается под рамку: длинное имя уменьшается или
переносится на вторую строку, совсем длинное — обрезается многоточием. Цвет подбирается так,
чтобы имя читалось на фоне: если цвет, предложенный ИИ, сливается с фоном, берётся светлый или
тёмный. На стандартном шаблоне ФИ стоит между подзаголовком и фотографиями. Если на новом дизайне
ИИ не нашёл подходящего места, ФИ не печатается, пока вы не укажете место сами (в Mini App —
переключатель «Печатать ФИ на билете» и нажатие на картинку).

## Данные

База — один файл SQLite `data/tickets.sqlite3`, там же хранится загруженный дизайн
(`data/template.png`). Для резервной копии достаточно скопировать папку `data/`.

Стандартный дизайн билета лежит в `assets/default_ticket.png`.

## Замечания

- В QR зашита ссылка вида `https://t.me/<бот>?start=t_<токен>`. Сканер в приложении читает из неё токен
  билета и сразу проверяет его, а обычная камера телефона просто откроет бота. Если сменить username
  бота, сканер в приложении и проверка по фото и по номеру продолжат работать.
- Модели на Groq периодически меняются, поэтому бот не привязан к одному названию (см. выше).
  Если «Проверить ИИ» пишет, что нет модели для картинок, выберите её вручную в «Настройках»
  (список — на console.groq.com/docs/vision).
- Дизайн билета загружайте в приложении файлом PNG или JPG в хорошем качестве.
