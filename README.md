# Бот для билетов с QR-кодом

Telegram-бот для администраторов мероприятия: выдаёт билеты с уникальным QR-кодом,
проверяет их на входе и ведёт список клиентов.

## Возможности

Бот отвечает **только администраторам**. Всем остальным он не пишет вообще ничего.

**Разделы**

- 🎟 **Новый билет** — ввод данных клиента → готовый билет (PNG) с уникальным QR.
  Обязательно только ФИ; группу, университет и телефон можно пропустить (кнопка «Пропустить»).
  Если на этот телефон билет уже выдавался, бот предупредит.
  На одни данные можно выдать сразу несколько билетов (до 10) — у каждого свой номер и свой QR.
- 📷 **Сканировать** — кнопка открывает камеру (см. ниже). Ещё можно навести обычную камеру
  телефона на QR и открыть ссылку, прислать боту фото QR или ввести номер билета.
  При повторном сканировании бот сообщает, что билет уже использован, и показывает время
  первого сканирования.
- 📋 **Список** и 🔎 **Поиск** — все купившие, выгрузка в TXT, повторная отправка билета.
- 📊 **Статистика** — сколько выдано, сколько прошло, разбивка по админам и университетам.
- 👥 **Админы** — добавление по нику (`@username`) или Telegram ID и настройка разрешений.
- 🎨 **Дизайн билета** — присылаете картинку (ФИ в ней быть не должно) → ИИ (Groq) находит место под QR
  **и место, где на билете можно печатать ФИ гостя** → предпросмотр с кнопками «Сохранить»,
  «Сделано неправильно», «Отмена». Если ИИ ошибся, можно описать словами, что исправить
  («ФИ должно быть над QR» — исправится только то, на что вы указали), или задать места вручную:
  `x y размер` для QR, `фи x y ширина высота` для ФИ, `без фи` — не печатать ФИ,
  `фи слева` / `фи по центру` / `фи справа` — выравнивание.
- 🗑 **Сброс списка** — полное удаление всех билетов (перед этим бот присылает копию в TXT).

**Разрешения**

Главному администратору (из `MAIN_ADMIN_IDS`) доступно всё. Каждому админу разделы включаются
по отдельности; по умолчанию — «Новый билет» и «Сканировать».

- «Список» и «Поиск» есть у всех, но без разрешения «Список и поиск» админ видит только билеты,
  которые выдал сам.
- Удалить билет может главный администратор или тот админ, который его выдал.
- Админ с разделом «Админы» может выдавать другим только те разрешения, которые есть у него,
  и не может менять свои.
- Админ, добавленный по нику, получает доступ, когда первый раз напишет боту `/start`.

**Чистый чат**

В каждом разделе новое сообщение бота заменяет предыдущее, а сообщения самого админа
убираются после обработки. В чате остаются меню, выданные билеты вместе с сообщением
«Проверьте данные», результаты сканирования и выгруженные файлы.

## Установка на сервер (Debian 10 / 11 / 12 / 13)

```bash
git clone https://github.com/NailGareev/Telegram-bot-for-mass-messaging.git
```

```bash
cd Telegram-bot-for-mass-messaging
```

```bash
sudo bash install.sh
```

Скрипт спросит только **токен бота** (от [@BotFather](https://t.me/BotFather)) и **Telegram ID
главного администратора** (его покажет [@userinfobot](https://t.me/userinfobot)), а остальное
сделает сам:

- поставит нужные пакеты и библиотеки (на Debian 10 и 11 системный Python слишком старый,
  поэтому скрипт ставит отдельный Python 3.12 в папку проекта, не трогая системный);
- проверит токен у Telegram;
- зарегистрирует бота как службу `ticket-bot` — он запустится сразу и будет стартовать сам
  после перезагрузки сервера.

Скрипт можно запускать повторно — например, после обновления:

```bash
git pull && sudo bash install.sh
```

Управление: `systemctl status ticket-bot`, `systemctl restart ticket-bot`,
журнал — `journalctl -u ticket-bot -f`.

## Обновление проекта из чата

Главный администратор обновляет бота, не заходя на сервер:

1. На GitHub откройте репозиторий → **Code → Download ZIP**.
2. Пришлите этот zip-файл в чат с ботом.
3. Бот покажет, сколько файлов добавится, изменится и удалится, и спросит подтверждение.
4. Нажмите **«Установить и перезапустить»** — через несколько секунд бот напишет, что обновился.

Что при этом происходит: бот ставит новые зависимости (если они изменились), проверяет пробным
запуском, что новая версия стартует, сохраняет копию текущей версии (`data/backup/`, последние 5)
и заменяет файлы проекта. Файл `.env`, база билетов, загруженный дизайн, ключи и настройки
не затрагиваются. Если новая версия не запустилась три раза подряд, прежняя возвращается сама.

Бот перезапускается сам, если запущен как служба (`install.sh`) или через `python run.py`.
При запуске вручную (`python -m bot`) он после установки остановится — запустите его снова.
Telegram не позволяет боту скачивать файлы больше 20 МБ; архив проекта весит меньше 1 МБ.
Обновление принимает только главный администратор.

## Настройки в боте

Ключ Groq (ИИ для смены дизайна, бесплатно на [console.groq.com/keys](https://console.groq.com/keys))
и адрес страницы-сканера задаются в самом боте: раздел **⚙️ Настройки** в чате или в Mini App.
Этот раздел есть только у главного администратора — другим админам его выдать нельзя.

## Запуск на своём компьютере

Нужен Python 3.10+.

```bash
python run.py
```

При первом запуске `run.py` создаст файл `.env` и попросит вписать в него `BOT_TOKEN` и
`MAIN_ADMIN_IDS`. После этого запустите `python run.py` ещё раз — он сам создаст виртуальное
окружение `.venv`, установит зависимости и запустит бота. Все следующие запуски — той же командой.

## Mini App

Все разделы бота доступны и как приложение внутри Telegram: кнопка **Mini App** слева от поля
ввода сообщения (она есть только у администраторов). В приложении — те же разделы и те же
разрешения, что и в чате; сканер открывает камеру и проверяет билеты один за другим, не закрываясь.
Билеты и выгрузки приложение присылает файлами в чат с ботом.

**Что есть в приложении сверх чата**

- **Уведомления о сканировании.** Пока приложение открыто, результат сканирования из чата
  (ссылка из QR камерой телефона, фото QR, номер билета) показывается в приложении: поверх
  любого экрана или прямо на экране сканера. Если приложение закрыто или не подтвердило
  получение за 10 секунд, результат приходит в чат, как раньше. Уведомление получает тот админ,
  который сканировал.
- **Массовый залив.** Загрузите список клиентов файлом `.txt` или `.docx` (до 5 МБ, до 300 клиентов за раз):
  ИИ сам найдёт в нём ФИ, группу, университет и телефон — в любом оформлении, в том числе в таблице, и
  учтёт количество билетов («2 билета»). Перед выдачей вы увидите всё, что он распознал, и можете
  поправить данные или убрать лишних; клиенты, которые уже есть в базе, отмечены и по умолчанию
  выключены. Готовые билеты приходят в чат архивами `.zip` и списком `issued.txt`.
  Без ключа Groq список разбирается по простым правилам: одна строка — один клиент в порядке
  «ФИ, группа, университет, телефон».
- **Билет на экране.** После выдачи и в карточке билета показывается сама картинка с QR.
- **Проверка по фото QR** — если камера Telegram недоступна (например, в Telegram для компьютера).

Telegram открывает мини-приложения только по HTTPS, поэтому бот при запуске:

1. поднимает на компьютере веб-сервер (порт `8080`, меняется через `WEBAPP_PORT`);
2. открывает к нему бесплатный туннель Cloudflare. Для этого нужна программа `cloudflared`:
   бот ищет её в системе и рядом с `run.py`, а если не находит — сам скачивает официальную
   сборку с GitHub в папку `data/` (Windows и Linux; на macOS — `brew install cloudflared`);
3. ставит администраторам кнопку Mini App с полученным адресом.

Адрес туннеля меняется при каждом запуске — бот сам обновляет кнопку. Регистрация в Cloudflare
не нужна. Если у вас есть свой сервер с доменом и HTTPS, укажите его в `WEBAPP_URL` (он должен
вести на порт бота) — тогда туннель не используется.

Модель Groq для разбора списков — `llama-3.3-70b-versatile`; другую можно указать в `.env`
строкой `GROQ_TEXT_MODEL=...`.

Отключить приложение: `MINI_APP=off`. Запретить автоматический туннель: `TUNNEL=off`.
Если туннель не поднялся, бот продолжит работать в чате как обычно, а причина будет в логе.

Адрес приложения в консоль не выводится — он сам попадает в кнопку Mini App.

## Кнопка «Сканировать» с камерой

Чтобы кнопка «Сканировать» сразу открывала камеру, боту нужна страница-сканер
(`docs/index.html`), доступная по HTTPS, — так устроены мини-приложения Telegram.
Проще всего выложить её через GitHub Pages:

1. В репозитории на GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**,
   выберите ветку с кодом и папку `/docs`, нажмите **Save**.
2. Через минуту страница появится по адресу вида `https://<логин>.github.io/<репозиторий>/`.
3. В боте откройте **⚙️ Настройки → Задать адрес сканера** и пришлите этот адрес —
   клавиатура у всех админов обновится сама.

После обновления `docs/index.html` перезапустите бота и нажмите `/start`: бот добавляет к адресу
метку версии страницы, чтобы Telegram не показывал старую копию из кэша.

Подойдёт и любой другой статический HTTPS-хостинг. Камера открывается в Telegram на телефоне;
в Telegram для компьютера на той же странице можно проверить билет по номеру.

Если адрес сканера не задан, кнопка работает по-старому: бот просит навести камеру телефона
на QR, прислать фото QR или ввести номер билета.

## Журнал

По умолчанию бот пишет в консоль только предупреждения и ошибки. Чтобы видеть подробный журнал
(запуск, каждое обработанное сообщение, запросы Mini App), добавьте в `.env` строку
`LOG_LEVEL=INFO` и перезапустите бота.

## ФИ на билете

На каждом билете печатается ФИ гостя. Шрифт — Inter (лицензия OFL, лежит в `assets/fonts/`),
он поддерживает кириллицу. Размер букв подбирается под рамку: длинное имя уменьшается или
переносится на вторую строку, совсем длинное — обрезается многоточием. Цвет подбирается так,
чтобы имя читалось на фоне: если цвет, предложенный ИИ, сливается с фоном, берётся светлый или
тёмный. На стандартном шаблоне ФИ стоит между подзаголовком и фотографиями. Если на новом дизайне
ИИ не нашёл подходящего места, ФИ не печатается, пока вы не укажете место сами (в Mini App —
переключатель «Печатать ФИ на билете» и нажатие на картинку).

## Данные

База — один файл SQLite `data/tickets.sqlite3`, там же хранится загруженный дизайн
(`data/template.png`). Для резервной копии достаточно скопировать папку `data/`.

Стандартный дизайн билета лежит в `assets/default_ticket.png`.

## Замечания

- В QR зашита ссылка вида `https://t.me/<бот>?start=t_<токен>`. Если сменить username бота,
  сканирование камерой у старых билетов перестанет открывать бота, но проверка по фото
  и по номеру продолжит работать.
- Vision-модели на Groq периодически меняются. Если бот пишет, что модель не найдена,
  укажите актуальную в файле `.env` строкой `GROQ_MODEL=...` (список — на console.groq.com/docs/vision).
- Новый дизайн лучше отправлять боту «как файл», чтобы Telegram не сжимал картинку.
